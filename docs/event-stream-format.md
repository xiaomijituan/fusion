# 事件流格式规范 · Event Stream Format v1

`schemaVersion: 1`。这份文档与 [scenario-format.md](./scenario-format.md) 平级，都是对外发布的规范：项目三的手册章节、社区传阅的战绩文件、将来的项目二，都按它读写。实现见 `src/lib/event-stream.ts`（写）与 `src/lib/review.ts`（读），设计来由见 ADR-0002 / ADR-0004 / ADR-0006 / ADR-0007。

## 一条总原则

**事件流是一局发生了什么的一份、也是唯一记录。** 它是追加式的，不回改、不压缩、不存折叠状态。要新视图（课后笔记、决策表、统计、导出）就从它做**投影**，不要新增第二份状态存储。

## 容器

JSONL：一行一个 JSON 对象，行之间无逗号，文件以换行结尾。第 1 行必须是 header，其后每行是一个事件。解析时忽略空行。

```jsonl
{"schemaVersion":1,"runId":"rxxxx-yyy","scenario":{"name":"fusion-default","version":"1.0.0"},"seed":1234567890,"startedAt":"2026-10-06T02:11:07.481Z","appVersion":"0.1.0","snapshot":{…}}
{"seq":1,"t":842,"n":0,"type":"decision","paneId":"p3","payload":{"kind":"answer","optionId":"b"}}
{"seq":2,"t":842,"n":0,"type":"transition","paneId":"p3","payload":{"from":"blocked","to":"working"}}
{"seq":3,"t":41120,"n":37,"type":"run.end","paneId":null,"payload":{"reason":"user","eventCount":2}}
```

## Header 行

| 字段            | 类型   | 必填 | 说明                                                                     |
| --------------- | ------ | ---- | ------------------------------------------------------------------------ |
| `schemaVersion` | 整数   | ✅   | 格式版本。**缺它就不是事件流文件**；大于当前版本 ⇒ 拒绝并提示升级应用    |
| `runId`         | 字符串 | ✅   | 一局的身份，形如 `r<毫秒时间戳 base36>-<seed base36>`                    |
| `scenario`      | 对象   | ✅   | `{ name, version }`——剧本 slug 与作者内容版本，两者都不解释语义          |
| `seed`          | 整数   | ✅   | 32 位无符号随机种子。同剧本 + 同种子 + 同决策序列 ⇒ 同事件流（ADR-0003） |
| `startedAt`     | 字符串 | ✅   | ISO 8601 UTC。事件行的 `t` 相对它计算                                    |
| `appVersion`    | 字符串 | ✅   | 产出它的应用版本                                                         |
| `snapshot`      | 对象   | ⬜   | 见下。缺省时笔记需要外部提供剧本才能补全文案                             |

### `snapshot`（ADR-0007）

只装复盘要读的那些字段，刻意不是整份剧本——进度条和机器描述永远不进笔记，所以导出保持小：

```
snapshot = {
  panes: [{ id, task }],
  tasks: [{ key, title, question: { text, options: [{ id, label }] } }]
}
```

`title` / `text` / `label` 是双语对象 `{ zh, en }`，规则与剧本一致（zh 必填、en 缺省回退 zh）。带 `snapshot` 的 `.jsonl` 是**自描述**的：别人发给你的文件，不装剧本也能打开成笔记。

## 事件行

| 字段      | 类型           | 必填 | 说明                                                |
| --------- | -------------- | ---- | --------------------------------------------------- |
| `seq`     | 整数           | ✅   | 1 起递增的行号，同一文件内唯一                      |
| `t`       | 整数(毫秒)     | ✅   | 距 `startedAt` 的墙钟毫秒，不为负。**不可跨局比较** |
| `n`       | 整数           | ✅   | tick 序号——因果时钟，可复现性比对用它（ADR-0006）   |
| `type`    | 字符串枚举     | ✅   | `transition` \| `decision` \| `run.end`             |
| `paneId`  | 字符串 或 null | ✅   | 事件属于哪个 pane；`run.end` 为 `null`              |
| `payload` | 对象           | ✅   | 形状由 `type` 决定，见下                            |

### 各 `type` 的 payload

**`decision`**——一次人的介入。写在前，它引发的 `transition` 写在后（顺序是投影能配对的前提）。

| 字段       | 类型   | 必填 | 说明                                                                                                   |
| ---------- | ------ | ---- | ------------------------------------------------------------------------------------------------------ |
| `kind`     | 枚举   | ✅   | `answer`（回答卡点）\| `dispatch`（下发任务）\| `kill`（关掉 pane）                                    |
| `optionId` | 字符串 | ✅   | `answer` 时是你选的那个选项 id；`kill` / `dispatch` 时是与 `kind` 同名的哨兵值 `"kill"` / `"dispatch"` |
| `text`     | 字符串 | ⬜   | 仅 `dispatch`：下发的那句话                                                                            |

**`transition`**——状态跃迁，由变更前后对比得出，所以新增一条变更路径不会忘记记录自己。

| 字段   | 类型   | 必填 | 说明                                               |
| ------ | ------ | ---- | -------------------------------------------------- |
| `from` | 字符串 | ✅   | 原状态：`working` \| `blocked` \| `done` \| `idle` |
| `to`   | 字符串 | ✅   | 新状态，取值同上                                   |

**`run.end`**——一局结束。`paneId` 恒为 `null`。

| 字段         | 类型 | 必填 | 说明                                                                     |
| ------------ | ---- | ---- | ------------------------------------------------------------------------ |
| `reason`     | 枚举 | ✅   | `left`（页面被关掉）\| `user`（主动离开）\| `export`（导出时补的合成行） |
| `eventCount` | 整数 | ✅   | 关闭前已有多少事件行                                                     |

导出一份还在进行中的局时，序列化会**追加**一条 `run.end{reason:"export"}`——交到别人手上的文件永远是闭合、良构的，而内存里那局继续增长。所以见到 `export` 表示"这份是中途导出的"，不是异常。

## 版本与兼容

- `schemaVersion` 是**格式**版本（本规范管）；header 里的 `scenario.version` 是**内容**版本（剧本作者管）。两者互不绑定。
- **窗口两端都挡**：接受 `schemaVersion ∈ [当前, 当前-1]`，也就是本规范下的 `1` 与 `0`。
  更大 ⇒ 报错要求升级应用；更小 ⇒ 报错指向一次性升级脚本；**非整数一律拒绝**，不"尽力解析"。
- 这一度只实现了上界（`-5`、`0.5` 会被当成 v1 收下），2026-10-07 补齐并各配了一条测试。
  注意 `0` 不是漏洞而是窗口内的合法值——早期文稿把它一起列成"错误接受"，那是错的。
- 加字段属兼容变更，但必须先改进本规范；删字段、改 `type` 语义、改 `payload` 形状都要 bump。

## 校验边界

- 解析器对**事件行里缺失的字段**是宽容的：`seq`、`t`、`n` 缺失时会给默认值。它对**身份信息**是严格的：第一行必须是一个带数值 `schemaVersion` 的头部，而且 `runId`、`scenario`、`seed`、`startedAt`、`appVersion` 这五个字段都要存在、类型都要正确。缺其中一个字段，或者把它们写成 `null`，或者把数字写成字符串，解析器都会回答"第 1 行不是事件流 header"。第一行之后的每一行都必须是合法的 JSON，并且带一个字符串类型的 `type`；不满足时整份文件被判为不合格，错误信息里会指出是第几行。这两条检查都是 2026-10-07 加的，而且是一条一条漏出来的：起初只检查 `schemaVersion`，所以有人把一份剧本 JSON 交给投影器时，它被当成头部收下，排出一张空表，也不说"这不是事件流"；加上"字段缺失就拒绝"之后，又发现一份五个字段全写成 `null` 的头部还是能过，因为解析器会给它填上默认值（`runId` 变成空字符串，`seed` 变成 0）。现在改成按类型检查，两种情况各有一条测试守着。
- 尺寸帽（单文件 ≤ 512KB、总 ≤ 2MB）只管**剧本导入**，不作用于事件流——事件流是应用自己产出的。外来文件仍应设阅读上限，属消费方的事。
- 事件流是数据：消费它时永不 eval、永不注入 DOM，文案一律走文本转义。
