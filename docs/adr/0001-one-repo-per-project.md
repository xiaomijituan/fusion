# 一个项目一个仓库，从此分开

分叉规划阶段想把现有模拟器做成三个方向（教学模拟器、真实编排工具、内容/社区），措辞在"三个 git 分支"和"两个项目"之间摇摆。决定：**每个项目独立仓库，不做分支分叉，不做 monorepo**。本仓库演化为项目一（开源教学模拟器 + 剧本格式）；项目三（中文可运行手册/社区内容）单独开仓，以组件或 iframe 方式嵌入项目一的构建产物；项目二（真实 agent 编排）等有真实多机实践后再独立开仓，项目一只为它留接口、不留实现。

## Considered Options

- **三条 git 分支各演化**：字面满足"分叉"，但代码从此不复用，剧本格式无法跨项目版本化。
- **Monorepo 多包**：共享内核方便，但项目三的内容发布节奏（文章、章节）会被项目一的发版绑住，而项目三要投递的是掘金/微信读书这类内容渠道，不是 npm。
- **一项目一仓库（选定）**：发布节奏、开源身份、对外叙事各自独立；代价是共享代码（剧本 schema、决策日志格式）要靠版本化的格式规范而不是共享源码来同步。

## Consequences

- 剧本格式和决策日志格式必须是**带版本号的公开规范**（文件 schema），因为跨仓库没有共享类型。
- 项目三嵌项目一时，只能依赖项目一的**发布产物**，不能 import 其源码；嵌入方式（iframe / web component / 构建产物拷贝）另立 ADR。
