# 决策时间线是唯一运行时产物，评分/笔记/项目二日志都是它的投影

项目一 v1 定为教学模拟器（可配置剧本、导入、导出），不做 Mini Metro 式评分游戏；但"导出这一局的决策时间线"从第一天就实现为**追加式结构化事件流**（谁、何时、面对什么问题、选了什么、后果），而不是导出时才拼出来的 Markdown。课后笔记、未来若做的评分、以及项目二的决策日志，都是这份事件流的投影/导出格式。

## Considered Options

- **导出时才拼 Markdown**：实现最快，但事件语义丢失，评分和跨仓库复用都要重新解析自由文本。
- **先做评分游戏再倒推记录**：记录 schema 会被游戏平衡性需求牵着走，而游戏设计是本项目最不可控的工作量。
- **事件流先行（选定）**：一份记录服务三个消费方；代价是 v1 就要为 schema 版本号和跨仓库兼容负责（见 ADR-0001 的后果）。

## Consequences

- 事件流 schema 是公开格式，带版本号；改字段等于改公共 API。
- v1 不存在"答错"这个概念：事件只记录选择与后果，不记录对错；评分若将来出现，是事件流之上的另一层。
