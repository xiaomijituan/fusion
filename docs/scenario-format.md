# 剧本格式规范 · Scenario Format v1

`schemaVersion: 1`。这份文档是对外发布的规范：项目三的手册章节、社区贡献的剧本、将来的项目二，都按它读写。
实现见 `src/lib/scenario.ts`，最小样例见 `scenarios/TEMPLATE.json`，检查命令 `npm run scenario:check`。

## 一条总原则

**剧本只能是数据。** 解析器用白名单（未知字段一律拒绝），导入的内容永不 eval、永不注入 DOM，台词只作为 React 文本节点渲染。想加行为，请提规范变更，不要在剧本里塞代码。

## 顶层字段

| 字段            | 类型     | 必填 | 说明                                            |
| --------------- | -------- | ---- | ----------------------------------------------- |
| `schemaVersion` | 整数     | ✅   | 格式版本，由本规范管。应用接受 `[当前, 当前-1]` |
| `id`            | 字符串   | ✅   | 剧本 slug，跨版本稳定（如 `fusion-default`）    |
| `version`       | 字符串   | ✅   | **作者自己的内容版本**，应用不解释它            |
| `name`          | 文本     | ✅   | 剧本标题                                        |
| `hosts`         | 数组(≥1) | ✅   | 机器。长度即机器数                              |
| `tasks`         | 数组(≥1) | ✅   | 任务。`key` 在本剧本内唯一                      |
| `panes`         | 数组(≥1) | ✅   | pane。长度即 pane 数；超过 24 给警告            |

没有 `extends`、没有 `$ref`、没有 `defs`、没有 `capabilities`——这些在 ADR-0006 里被明确拒绝，理由：文件必须自包含（ADR-0005「文件即分享物」）。

## 文本字段（双语规则）

任何文本字段可写成两种形式：

```json
"role": "笔记本"
"role": { "zh": "笔记本", "en": "laptop" }
```

- **中文必填，英文选填**；缺英文时应用自动回退成中文，渲染层不做语言判断。
- `{}` 形式里出现 `zh`/`en` 以外的键 → 报错（未知字段）。
- 空字符串算缺失。

## hosts[]

| 字段    | 类型           | 必填               |
| ------- | -------------- | ------------------ |
| `id`    | 字符串（唯一） | ✅                 |
| `role`  | 文本           | ✅                 |
| `place` | 文本           | ⬜ 缺省沿用 `role` |

## tasks[]

| 字段               | 类型           | 必填 | 说明                           |
| ------------------ | -------------- | ---- | ------------------------------ |
| `key`              | 字符串（唯一） | ✅   | pane 用它引用任务              |
| `project`          | 字符串         | ⬜   | 机房里显示的项目名             |
| `title`            | 文本           | ✅   | 任务一句话                     |
| `lines.zh`         | 字符串数组(≥2) | ✅   | 剧本台词：agent 自己往下报的行 |
| `lines.en`         | 字符串数组     | ⬜   | 行数必须与 `zh` 相同           |
| `question.text`    | 文本           | ✅   | 卡点问题                       |
| `question.options` | 数组(1–6)      | ✅   | `id` 唯一，`label` 为文本      |

### `kill` 是保留 id

**只有 id 恰好为 `kill` 的选项会关掉 pane**，其余任何 id 一律"记下继续推进"。剧本没写 `kill` 时解析器自动补一个（中文"关掉"/英文 "Kill it"）。把 `kill` 拼错（编辑距离 ≤2）会得到一条**警告**，导入仍然成功——因为拼错的 id 只会被当成普通选项，这正是最容易被忽略的坑。

## panes[]

| 字段       | 类型                               | 必填 | 缺省                            |
| ---------- | ---------------------------------- | ---- | ------------------------------- |
| `host`     | 字符串                             | ✅   | — 必须是本剧本已定义的 host id  |
| `task`     | 字符串                             | ✅   | — 必须是本剧本已定义的 task key |
| `kind`     | `claude`/`codex`/`opencode`/`grok` | ⬜   | `claude`                        |
| `status`   | `working`/`blocked`/`done`/`idle`  | ⬜   | `working`                       |
| `progress` | 整数 0–100                         | ⬜   | `20`                            |

**pane 的 id 不在文件里写**：由文件顺序派生成 `a1, a2, …`，同一份文件每次解析得到同一批 id——事件流靠它对齐（ADR-0004）。机器内的序号同样自动编号。

## 版本与迁移

- `schemaVersion` 由规范管，`version` 由作者管，两者互不相干。
- 应用接受 `schemaVersion ∈ [当前, 当前-1]`：**迁移窗口只有一个大版本**。太新 → 提示升级应用；太旧 → 指向一次性升级脚本。
- 导出/分享出去的剧本一律内联展开、按当前版本写出，保证自包含。

## 尺寸与硬限制

| 限制                     | 值                  |
| ------------------------ | ------------------- |
| 单文件                   | ≤ 512 KB            |
| 浏览器内全部导入剧本合计 | ≤ 2 MB              |
| pane 数                  | 软帽 24（超出警告） |
| 每任务台词               | ≥ 2 行              |
| 每卡点选项               | 1–6 个              |

## 提交前自查

```bash
npm run scenario:check              # 校验 scenarios/ 下全部文件
npm run scenario:check -- 我的.json  # 校验指定文件
npm run scenario:check -- --strict   # 警告也算失败
```

输出形如：

```
FAIL scenarios/my.json: panes[2].host — 找不到主机「omarchy-3」。本剧本的主机有：omarchy-1、omarchy-2、framework。
     Unknown host "omarchy-3". This scenario defines: omarchy-1, omarchy-2, framework.
     ↳ 是否想写「omarchy-2」？ / Did you mean "omarchy-2"?
```

问题**一次报全**，不是第一条就停。
